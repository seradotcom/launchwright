# Requirements traceability

The private product specification used to start Launchwright contains 196 requirement records across domain model, SDK, sources, capture, process, claims, graph, verification, media, docs, localization, channels, review, publishing, UX, API, security, data, operations, extensions, QA and go-to-market concerns.

The private specification text is intentionally not redistributed in this AGPL repository. This file records implementation status without copying that source. `requirements-index.json` preserves all 196 requirement IDs, acceptance-test IDs, scenario IDs, scope and priority so implementation evidence can be attached without republishing the private prose.

## Current implemented foundations

- Durable resource identity, optimistic concurrency, tombstones and append-only audit events, plus exact entity revision history in schema v2 with bounded history reads/diffs and explicit legacy migration that never invents missing revisions.
- Native SDK dispatcher/bridge, exact digests, cancellation, recovery and bounded observation.
- Build/source/target/scenario/anchor contracts with explicit authorization and provenance.
- Claims, CopyBlocks, availability and ReleaseContract denominators without fabricated coverage.
- Immutable text artifacts, exact candidate manifests and freshness invalidation.
- RS-GRF-01..10 application-side Project Graph integration: immutable owner-admitted canonical projections at the pinned Semwright schema/SHA; strict declared/observed/imported/heuristic provenance; visible-resource-only bounded impact; preserved UNKNOWN frontiers; authority-free exact-revision impact proposals and coalescing; reuse identities bound to target/toolchain/fixtures/templates/verifiers/tenant/rights/permissions; exact built-vs-pending rebuild receipts; mandatory final-delivery revalidation; and percentages only over an explicitly safe authorized visible denominator. R21 additionally drives the exact Semwright Broker Project Graph over an owned file-backed fixture and carries its bounded query/impact/export result through the real Launchwright NativeDriver graph profile, with a separate `project.manage` denial control and daemon-restart persistence. Launchwright does not become the Graph traversal engine or invent dependency certainty that Semwright did not observe.
- RS-EFX immutable-artifact canonical readback custody: the exact pinned Native SDK Effects schema/scope is consumed rather than reimplemented; exact protected-spec/result bytes and digests are retained; decisive results must cover the exact bound artifact set; PASS requires explicit owner admission; FAIL is never softened; artifact/scenario/input drift invalidates old effective PASS; and every stored receipt keeps `execution_authority:false` plus `scenario_effects_covered:false`. Real native/browser/Godot mutation effects, noninterference and Host admission remain Semwright-owned.
- Application-local document change proposals for CopyBlocks and deliverables: proposal creation never mutates content, application requires an exact base revision, stale proposals fail closed, and human-owned/whole-document content requires explicit acknowledgement.
- Capture contract v2 covering receipt correlation, readiness, anchor uniqueness, build drift, demo-data labeling, derivative lineage, isolation, bounded cleanup, ordered segments and no-fake-UI eligibility; technical state remains UNKNOWN.
- Owned DeltaDesk A/B cross-system browser laboratory: a dedicated heavy CI lane executes the exact pinned Semwright Chromium semantic adapter, verifies release-sensitive A/B semantics and screenshot bytes, and records the resulting external adapter evidence through capture-contract v2 as `IMPORTED_UNVERIFIED`; no Platform job, Host admission or technical PASS is fabricated.
- RS-MED cross-system real-media bridge: the selective Composition lane binds the exact retained DeltaDesk A/B screenshot hashes to a 600-frame/20-second rational timeline, derives an explicitly receipted even-canvas presentation frame set by padding at most one right/bottom pixel with the owner-pinned FFmpeg (no crop, rescale or synthetic UI), encodes that derivative through the pinned Semwright MLT provider inside Driver Host, retains the resulting H.264/AAC MP4, and independently executes Semwright's canonical Composition + Audio AV E2E on the same immutable Semwright SHA. `src/composition-evidence.mjs` rejects source/hash/SHA/normalization drift and intentionally reports `PARTIAL`/technical `UNKNOWN` because the two proofs are not yet a single owner-admitted Composition recipe.
- Immutable verifier records, coverage/omissions/findings and non-state-changing waivers.
- Versioned channel packages plus authenticated deterministic private bundles containing the exact channel manifest, candidate manifest and pinned artifact bytes.
- Versioned channel profiles, exact package generation and external receipt/recovery state.
- Publish-side application contracts for RS-PUB-01..08: editable ReleaseTemplate drafts, immutable ProductVersion pins, bounded consumer parameters/budgets, exact deployment lifecycle, per-consumer invocation isolation/idempotency and export/import without transferring authority. Actual external Platform acceptance remains separate.
- Portable snapshot/restore v2 with exact stored revision history, migration provenance, epoch/generation rotation, uncertain-intent suspension and backward-compatible v1 restore without historical reconstruction.
- Operations-side foundations for RS-OPS-01..10: application-owned reservations stay under the requested work ceiling; provider usage-event IDs are idempotent; finalization/corrections retain exact measured receipt bases; estimated/measured and BYO/platform-managed costs stay distinct; externally observed cost/runtime overruns are preserved rather than rewritten; job/native/artifact correlations are bounded; billing callbacks are test-only and cannot replay work or mutate evidence; measurements keep query/mutation/snapshot/restore distinct from unavailable Platform admission/queue/render phases; `doctor` is read-only; and clean-room reproduction uses documented commands without author secrets or hidden paths. Canonical Platform ledger, real billing, executor hard-stops and production observability acceptance remain external.
- Loopback HTTP/UI security, bounded payloads and session-cookie authentication.
- Versioned extension descriptors now support exact prepared-use pins, safe generic metadata views, resolved-rights enforcement, retirement-aware start blocking, schema-major rejection, bounded generic result receipts and drift inspection. Owned executable DeltaCLI/DeltaRender fixtures plus a bounded mobile-import fixture exercise non-DOM source, renderer and import-only paths without claiming canonical Driver Host or device-capture authority.

## Integration-dependent / not accepted

Canonical real-product capture across customer targets and Platform admission (the owned DeltaDesk Semwright Chromium adapter lane is established only as imported-unverified cross-system evidence); real customer/project Graph discovery and provider-specific dependency extraction beyond the owned R21 file fixture, plus non-fixture scope/tenant acceptance; canonical execution-effect/noninterference and scenario-effect admission beyond the integrated immutable-artifact Effects readback; one owner-admitted Composition recipe that consumes the real DeltaDesk capture set end-to-end (the real-media MLT/Driver Host leg and canonical AV coordinator leg are deliberately separate); real Platform recipe/job execution; canonical verifier runtime admission; remote teams; real cross-account Platform Publish execution/output ACLs/external activation; mobile/Godot target acceptance; ChatGPT Plugin host acceptance; production deployment. The stored Graph projection and R21 Broker/Native integration do not replace those external authorities.

Requirement completion is therefore not represented as a single vanity percentage. Evidence is tracked by exact behavior, SHA and acceptance lane in `ACCEPTANCE.md`.
